# tron 0.0.0.3 (unreleased)

Changes since 0.0.0.2.

- Added: Units (doc/units.md): small read tools with one job each and a declared input and output type, in six new
  built-in programs that can be switched off per program or per tool in Setup > tron. ini: `ini_resolve`, `ini_diff`,
  `ini_list`; tpl: `tpl_resolve`, `tpl_lint`, `tpl_source`; node: `node_read`, `node_tree`, `node_find`,
  `node_versions`; class: `class_describe`, `class_list`, `class_diff`; layout: `layout_list`, `layout_read`,
  `layout_rule_list`, `layout_rule_resolve`, `layout_block_definitions`; role: `role_describe`, `role_user_find`.
  Each checks the calling user's own policies (setup/setup, content/read with its limitations, content/versionread,
  class/*, explayouts/read, role/*), is audited, masks secrets and e-mail addresses, and declares its output schema.
- Added: The type catalog (`tronUnitTypes`: refs, values, lists and which value provides which ref) and the unit
  declarations in the program manifests (`"units"`, read by `tronUnitCatalog`, whose `contracts()` gives every unit's
  types and output schema).
- Added: `tron_pipe`, which chains read units by type like a Unix pipe ("node.find class=article limit=3 | node.read |
  tpl.resolve"), fans lists out item by item, calls identical arguments once, runs every step as its own checked and
  audited call, and stops at 8 steps and 100 calls; `explain` shows the plan. The resource `tron://units` lists the
  units and types. Both are offered only where the units are.
- Added: doc/units-roadmap.md: write units with a dry run, data movers, recipes and planning from expai.
- Updated: The server offers itself to the core program as the environment service `tron.server`.
- Updated: The tests that listed the built-in programs read them from programs/ instead.
