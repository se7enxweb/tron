# tron 0.0.0.4 (unreleased)

Changes since 0.0.0.3.

- Added: The API coverage inventory (doc/api-coverage.md): `bin/php/tron-inventory.php` walks an installation and lists
  every API point with its metadata: modules and their views and policy functions, template fetch functions,
  operations, template operators, datatypes, workflow event types, the public methods of the content, class, user and
  role services and of extension services, INI files and blocks, console commands, bin/php scripts, cronjob parts and
  expqueue job types. Each point gets a risk class (read, write, admin, dangerous) from its own declaration or its
  name, whether tron covers it and by which tool or unit, or the plan for it. Written as JSON (one point per line,
  doc/api-coverage.json or var/tron/api-coverage.json) and as the generated page doc/api-coverage.md. Other MCP
  servers of an installation and private client projects are left out by pattern.
- Added: The built-in program `system` (doc/system-adapters.md), generic adapters that reach the whole installation:
  `system_catalog` and `system_coverage` (the catalog), `system_fetch_describe` and `system_fetch_call` (any read
  template fetch function, parameters checked against function_definition.php, a list fetch capped at 100),
  `system_operator_eval` (read template operators on a value, never on template code), `system_module_view_describe`
  and `system_module_view_read` (any module described, read views rendered as title, path, text and links),
  `system_console_command` and `system_cli_script` (reviewed console commands and their scripts, read-only or as their
  own dry run, as journaled jobs with a timeout) and `system_queue_jobs` and `system_queue_job` (expqueue). Every
  adapter runs as the calling user, inside a database transaction that is rolled back, declares its output schema,
  and refuses write, admin and dangerous points until their dry-run twin exists.
- Added: tests/unit/SystemAdaptersTest.php (the inventory on a fixture installation, every adapter on fixture
  sources, a contract fuzz run of every adapter) and tests/kernel/system_adapters_run.php (the proving run against a
  real installation).
- Updated: The release fields, the built-in program manifests and the schema file headers move to 0.0.0.4.
