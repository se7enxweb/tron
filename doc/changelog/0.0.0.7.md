# tron 0.0.0.7 (unreleased)

Changes since 0.0.0.6.

- Added: Skills (doc/skills.md). A skill is a reviewed chain of units written as data: typed, bounded parameters with
  examples and CLI options, the units it runs with their argument wiring, declarative steps between them (where, pick,
  map, sort, limit, count, group, sum, min, max, distinct, pluck, flatten, age, merge, text, test, assert, each),
  guards, and the schema of its answer. It holds no code, runs as its caller and cannot do more than the caller could
  by hand: every unit call goes through the server's scope, policy, argument, audit and redaction checks, and each
  unit answer is redacted again before a step sees it.
- Added: The standard for skill packs and programs shipped from extensions (doc/extension-conventions.md): folder
  layout, the `[SkillPack_<id>]` settings group, naming, manifest reference, versions, license and author, units and
  programs a pack needs, testing, translations, docs, security, deprecation, remixing, with a worked example
  extension (the test fixture `expskillsexample`). The validator enforces it: a pack that breaks it is refused with
  every reason and nothing of it is offered.
- Added: The skill lifecycle: draft, validate (standard, units, the policy simulator for every unit and guard, every
  example run read-only, output schema, redaction), approve by a person, live. An approval holds for exactly one
  manifest (its SHA-256); every draft, fork, approval and revocation is kept in the table `tron_skill`, created on
  first use, and switched-off packs in `tron_skill_pack`.
- Added: The program `skill`: `skill_list`, `skill_show`, `skill_packs`, `skill_run`, `skill_draft` and `skill_fork`
  (both with a dry run) and `skill_validate`. Every live skill is also its own MCP tool and prompt `skill_<name>`,
  registered once every program and engine is loaded, so a skill whose unit is missing is never offered.
- Added: The harness `bin/php/tron-skills.php harness`: every example of every skill on tron's SQLite fixtures
  (centre tickets and planted canaries: a password, a tron token, an e-mail address) and read-only on a real
  installation; results with the manifest hash in each pack's `proof.json`. Also `lint`, `try`, `unit`, `list`,
  `show`, `packs`, `counts`, `run`, `validate`, `install`, `export`, `export-local`.
- Added: 16 starter packs with 358 skills in `share/skills`: centre-tickets, centre-planning, centre-decisions,
  centre-triage (writes, parked until wave B), content-inventory, classes-and-schema, media, seo, i18n,
  ini-and-settings, site-audit, layouts-and-blocks, templates-and-overrides, users-and-roles, ops-reports,
  katalyst-reports. Each pack has a README and a page in doc/skill-packs/.
- Added: Setup > tron > Skills: packs with their providing extension, version, license and state; skills with search,
  state and tag filters; one skill with parameters, steps, examples, proof, runs and versions; Prove and approve,
  Approve ready skills, Revoke, switching a pack, Fork into a local pack, all behind "Verify it's you". English and
  German.
- Added: tron.ini `[SkillPackSettings]` (TronPacks, ExtensionScan, Disabled[]).
- Updated: The tool counts of the tests and the cookbook's expected output include the seven `skill_*` tools.
