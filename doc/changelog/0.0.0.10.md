# tron 0.0.0.10 (unreleased)

Changes since 0.0.0.9.

- Updated: Approving a skill in Setup > tron > Skills (and any caller of tronAdminSkillsData without its own server)
  proves the skill through the installation's own access check, eZUser::hasAccessTo(), as the approving
  administrator. Before, it fell back to the administration's listing server, whose access checker grants only its
  internal principal, so every approval was refused with "the user may not run every unit of the skill", even for an
  administrator whose role grants every module and function. Outside an installation, without a server that checks
  the administrator's own policies, approving now says so instead.
- Added: A test that an all-modules role and a tron-wide role prove and approve a skill like the kernel's check, that
  a limited grant does not where the unit takes none, and that the skill's policy simulation and tron_policy_check
  give the access checker's own answer for each.
