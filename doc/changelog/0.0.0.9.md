# tron 0.0.0.9 (unreleased)

Changes since 0.0.0.8. The root programs landed between 0.0.0.5 and 0.0.0.6 without a version of their own; this
version names them.

- Added: The root programs web, browser, validate, diff and api, 41 tools that skills build on
  ([root-programs.md](../root-programs.md)): one SSRF guard for every outbound request (http and https only, every
  resolved address public, mesh and metadata addresses named, IPv4 inside IPv6 judged by the IPv4,
  internal names refused before DNS, the connection pinned to the checked address and compared afterwards, every
  redirect hop checked again), robots.txt respected, size and time limits.
- Added: Browser engines are installed before they are used: `browser_install` (or `xsh tron:browser:install
  <engine>`) adopts a build of the pinned Playwright version already on the runner node or downloads it into
  `/var/lib/tron/browsers`, starts it once as proof and records the checksum of its executable; every job tool
  refuses an engine that is not installed. Jobs run on `[BrowserSettings] RunnerHosts[]` only, started by the
  systemd units `tron-browser.path` and `tron-browser.service` (`xsh tron:browser:setup`).
- Added: Setup > tron > Diff and the template part `tron/parts/diff.tpl` (policy `tron/diff`).
- Added: Policies `web`, `browser`, `browser_install`, `validate`, `diff`, `api_read`, `api_write`, `api_http`;
  settings groups `[RootProgramSettings]`, `[WebSettings]`, `[BrowserSettings]`, `[ValidateSettings]`,
  `[ApiSettings]`. Without `[RootProgramSettings] Enabled=enabled` the five programs offer no tool; without
  `[WebSettings] Network=enabled` no request and no DNS lookup is made.
- Updated: Browser job answers give artifact paths relative to the queue directory also when the queue is
  configured as a relative path; waiting for a job counts its looks instead of timing them.
- Updated: The fuzz world switches the root programs on, so the contract fuzzing covers their tools too (without
  network: every request is refused there).
